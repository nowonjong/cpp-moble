# 프로토타입 검증 결과

검증일: 2026-09-09

## 빌드 및 실행

- Windows에서 Visual Studio 2022의 v143 도구로 C++17, x64 Debug 및 Release 빌드 성공.
- 한글 입력 수정 후 두 구성과 테스트 프로젝트를 다시 빌드했다.
- 실행 파일: `bin/Release/prototype.exe`
- 간편 실행: 루트 폴더의 `play.cmd`

## 자동 검사 결과

**30개 테스트 그룹 통과, 실패 0개.**

- UTF-8 유효성, 한글 음절 분리, 사전 파일의 중복·잘못된 행·누락·읽기 오류.
- 연결·중복·길이 검사, 턴별 3회 기회, 점수, 승패, 포기·중단, 재시작.
- 쉬움/보통 AI의 후보 선택, 보통 AI의 다음 후보 수 계산, 상태 변경 여부.
- 힌트 비용·횟수·실패 처리.
- 기록 저장·불러오기, 손상 파일 보존, 초기화 전 백업, 저장 실패.
- 메뉴부터 게임·설정·통계까지 이어지는 흐름.
- 무작위 상태 2,000개에서 인덱스 검색 결과와 전체 순회 검색 결과 일치.
- 제공 사전 1,159개 단어로 쉬움/보통 합계 200판 자동 진행 완료.

200판의 결과는 사용자 승리 88판, 패배 112판, 정상 사용자 입력 383회였다. 정해진 테스트 입력 전략과 난수 시드로 검사한 값이며, 실제 사용자의 승률이나 난이도 평가를 뜻하지 않는다.

원본 로그: [tests/results.txt](../tests/results.txt)

## 실제 Windows 콘솔 확인

별도 테스트 사전으로 다음 흐름을 직접 확인했다.

`컴퓨터: 사과 → 사용자: 과자 → 컴퓨터: 자동차 → 사용자: 차표`

- 한글 입력이 정상 단어로 승인됨.
- 사용자 20점 승리.
- 결과 저장 후 통계 메뉴에 반영됨.

초기 콘솔 검사에서 발견한 한글 입력 문제를 수정했다. 이후 위 콘솔 흐름과 전체 자동 검사를 다시 통과했다. 게임 및 기록 검사는 별도 테스트 폴더와 임시 폴더에서 진행했다.

## 다시 검사하는 방법

Visual Studio 개발자 명령 프롬프트에서 다음을 실행한다.

```bat
cd /d C:\TeamProject2\prototype
msbuild tests\word_game_tests.vcxproj /p:Configuration=Debug /p:Platform=x64
bin\Tests\word_game_tests.exe data\words.txt
```

테스트 실행 파일은 기록 검사용 임시 폴더를 별도로 만든다.

## 검증 범위

- 현재 PC의 Windows 콘솔과 빌드 환경에서 확인했다. 팀원 PC에서는 처음 실행할 때 한글 입력과 빌드를 확인하면 된다.
- 두음법칙, 제한 시간, 연속 정답 보너스는 이번 버전에 포함하지 않았다.
- 사전은 제공 목록에 포함된 단어만 인정한다. 로더의 형식 검사는 실제 국어사전 등재 여부나 품사를 판정하지 않는다.
- 여러 프로그램이 같은 기록 파일을 동시에 수정하는 상황은 지원 범위 밖이다.
