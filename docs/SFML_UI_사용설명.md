# SFML UI 사용설명

## 1. 실행하고 한 판 해 보기

1. `C:\TeamProject2\prototype\play.vbs`를 더블클릭합니다. 또는 `bin\Release\prototype.exe`를 실행합니다.
2. 홈에서 **쉬움 / 보통**, **힌트 켜짐 / 꺼짐**을 선택합니다. 설정은 새 게임을 시작할 때 적용됩니다.
3. **새 게임 시작**을 누르면 컴퓨터가 첫 단어를 냅니다.
4. 왼쪽 큰 단어의 마지막 음절에 맞춰 입력칸에 단어를 적고 **제출**을 누릅니다.
5. 게임이 끝나면 **다시 도전**으로 같은 설정의 새 게임을 시작하거나 **홈으로** 돌아갑니다.

한글 단어를 입력하고 **Enter를 한 번 누르면 조합 확정과 제출이 함께 처리됩니다.** 제출 버튼도 사용할 수 있습니다. 입력칸은 일반 Windows 입력칸처럼 커서 이동, 선택, 복사·붙여넣기, Backspace를 지원합니다.

## 2. 화면에서 확인할 것

| 화면·버튼 | 하는 일 |
|---|---|
| 홈 | 난이도·힌트 선택, 사전 단어 수·내 기록 확인, 게임 시작 |
| 큰 단어와 안내 | 직전 단어와 다음 단어의 시작 음절 확인 |
| 제출 | 입력한 단어의 형식·사전·연결·중복 검사 |
| 내 점수 / 남은 기회 | 현재 점수와 이번 턴의 남은 제출 기회 확인 |
| 힌트 보기 | 5점을 사용해 가능한 단어의 시작 음절과 음절 수 확인 |
| 이어온 단어 | 사람과 컴퓨터가 사용한 단어 확인. 마우스 휠로 이전 기록 보기 |
| 전적 | 최신순 게임 기록, 승리·패배·최고 점수·중단 횟수 확인 |
| 규칙 | 현재 게임 규칙 확인 |
| 게임 포기 | 확인 후 이번 판을 패배로 끝내기 |

컴퓨터가 단어를 고르는 동안에는 제출할 수 없습니다. 진행 중 **홈**을 누르면 포기 확인 창이 뜨며, **전적 / 규칙**은 게임이 끝난 뒤 열 수 있습니다. 창 크기를 바꾸면 화면과 입력칸의 위치도 함께 조정됩니다.

## 3. 규칙과 기록 정책

- 사전에 있는 **완성된 한글 2~64음절** 단어를 사용합니다. 사용한 단어를 다시 낼 수 없고 두음법칙은 적용하지 않습니다.
- 내 턴마다 기회는 3번입니다. 잘못된 제출은 1번을 사용하며, 빈 입력은 기회를 사용하지 않습니다.
- 정답은 10점입니다. 컴퓨터가 응답하고 다음 내 턴이 되면 기회가 다시 3번으로 채워집니다.
- 이어갈 합법 단어가 없는 쪽이 패배합니다. 내가 같은 턴에 3번 틀려도 패배합니다.
- 힌트는 홈에서 켠 경우 한 판 최대 3회입니다. 점수가 5점 이상이어야 사용할 수 있습니다.
- **포기 = 패배**, 진행 중 **창 닫기 → 중단하고 닫기 = 중단**입니다. 확인 창에서 취소하면 계속할 수 있습니다.
- 중단한 판의 기록과 점수는 남지만, 승패 통계와 최고 점수에는 포함하지 않습니다.

기록은 `data\records.txt`에 저장하며, 다음 실행 때 불러옵니다. 당시 난이도와 힌트 설정도 게임 기록에 포함합니다. 홈의 설정 선택 자체를 다음 실행까지 별도 저장하지는 않습니다.

## 4. 사전과 저장 오류

단어를 늘리려면 `data\words.txt`를 **UTF-8, 한 줄에 한 단어** 형식으로 편집한 뒤 프로그램을 다시 실행하세요. 중복과 잘못된 행은 제외합니다. 사전 등록 여부가 게임 판정 기준이므로, 실제 단어여도 사전에 없으면 인정하지 않습니다.

| 증상 | 확인할 내용 |
|---|---|
| 사전을 읽을 수 없다는 화면 | `data\words.txt`의 위치·UTF-8 형식·사용 가능한 단어 유무 |
| 시작할 수 없다는 안내 | 적어도 첫 단어에서 다음 단어로 연결되는 조합이 있는지 확인 |
| 홈에 기록 저장 중지 안내 | 기존 기록을 읽지 못한 상태. 파일을 확인하거나 **기록 복구** 사용 |
| 게임 종료 후 저장 실패 안내 | 기록 파일과 폴더의 쓰기 권한·파일 상태 확인 |
| DLL이 없다는 실행 오류 | `bin\Release`의 DLL을 실행 파일과 함께 복사했는지 확인 |
| 글꼴 로드 오류 | Windows에 맑은 고딕(`Fonts\malgun.ttf`)이 있는지 확인 |

**기록 복구 → 백업 후 초기화**는 기존 파일을 백업하고 새 기록으로 시작합니다. 백업에 실패하면 원본을 유지합니다. 기록이 손상된 상태에서도 게임은 할 수 있지만 전적 저장은 중지됩니다.

## 5. Visual Studio에서 개발하기

`prototype.sln`을 열어 **Visual Studio 2022 / v143 / x64 / C++17**로 빌드합니다. SFML은 프로젝트에 포함된 **3.0.2 VC2022 x64** 버전을 사용합니다. SFML 2.x 예제의 코드를 그대로 붙이면 이벤트·문자 출력 API가 달라 컴파일되지 않을 수 있으므로, 포함된 헤더와 현재 코드의 사용법을 기준으로 수정하세요.

`Sfml.props`가 include·lib 경로와 링크 설정을 넣고, 빌드 후 필요한 DLL을 출력 폴더로 복사합니다. Debug는 `/MDd`, Release는 `/MD`를 사용합니다. 프로젝트의 기존 설정 뒤에서 이 속성 시트를 적용하도록 되어 있으므로 직접 `/MT`로 바꾸거나 x86 라이브러리와 섞지 마세요.

다른 PC로 실행본을 보낼 때는 **Release**를 빌드하고 DLL·`data`·라이선스를 함께 보냅니다. 폴더 전체를 복사하는 방법이 가장 간단합니다.

## 6. 6번 담당이 읽을 순서

| 순서 | 파일 | 먼저 이해할 부분 |
|---|---|---|
| 1 | `SfmlMain.cpp` | 데이터 경로를 찾고 `SfmlApplication`을 생성해 실행 |
| 2 | `SfmlApplication.h` | 화면 종류, 현재 화면, 버튼과 입력칸 등 UI 상태 |
| 3 | `SfmlApplication.cpp`의 `run()` | 이벤트 확인 → 입력 처리 → 컴퓨터 턴 진행 → 화면 그리기 |
| 4 | `drawHome()` / `drawGame()` 등 | 화면별 글자·패널·버튼 배치 |
| 5 | `click()` / `submit()` | 버튼 이름에 따라 기존 게임 기능 호출 |
| 6 | `NativeTextInput.h/.cpp` | Windows 입력칸의 한글 조합·Enter와 UTF-8 문자열 전달 |

흐름은 **입력칸·버튼 → SfmlApplication → GameManager → 기존 규칙·AI·기록 → 결과를 화면에 출력**입니다. 화면을 꾸밀 때는 `draw...()`를, 버튼 동작을 바꿀 때는 `click()`을 먼저 찾으면 됩니다.

사전은 1번, 한글 단어 검사·규칙은 2번, AI는 3번, 게임 상태·점수는 4번, 기록·설정 자료형은 5번의 기존 코드를 사용합니다. **Windows 입력창의 한글 조합 처리**와 **입력된 단어가 규칙에 맞는지 검사하는 처리**는 역할이 다릅니다. 점수·승패·저장을 UI에 중복 구현하지 말고 기존 `GameManager`의 결과를 표시하세요.

기존 `main.cpp`, `Application.cpp`, `ConsoleUI.cpp`는 콘솔 참고·테스트용이며 기본 게임 빌드 대상에서 제외했습니다. 현재 게임의 시작 파일은 `SfmlMain.cpp`입니다. Windows 입력칸 내부 구현은 먼저 인터페이스 사용법부터 이해해도 화면 작업을 진행할 수 있습니다.
