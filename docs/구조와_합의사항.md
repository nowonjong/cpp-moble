# 역할별 파일과 프로토타입 적용 기준

## 1. 역할별 파일

| 역할 | 파일 | 책임 |
|---|---|---|
| 1번 사전 | Dictionary.h/.cpp, data/words.txt | 로딩·정제 집계·검색·시작 음절 인덱스 |
| 2번 한글·규칙 | Utf8Util.h/.cpp, RuleChecker.h/.cpp | UTF-8 디코딩, 음절, 입력·사전·중복·연결 판정 |
| 3번 AI | ComputerAI.h/.cpp | 합법 후보, 시작 후보, 쉬움·보통 선택 |
| 4번 게임 | GameTypes.h, GameManager.h/.cpp | 턴·기회·점수·사용 단어·승패·재시작 |
| 5번 기록·설정 | Settings.h, RecordTypes.h, RecordManager.h/.cpp, HintSystem.h/.cpp | 설정 자료형, 결과 보관·복원·통계, 힌트 내용 |
| 6번 UI·통합 | ConsoleUI.h/.cpp, Application.h/.cpp, main.cpp | 한글 콘솔 입력, 메뉴·화면, 모듈 연결 |

main.cpp는 실행 경로와 Windows 콘솔을 준비합니다. Application.cpp는 객체를 만들고 메뉴 및 게임 루프를 연결합니다. 게임 상태 변경은 GameManager가 담당합니다.

## 2. 읽기 순서

1. Settings.h, RecordTypes.h, GameTypes.h로 자료의 모양 확인
2. Application.cpp에서 전체 호출 순서 확인
3. 자기 역할의 헤더에서 입출력 확인
4. 자기 역할의 cpp에서 구현 확인
5. tests/Tests.cpp에서 기대 동작 확인

5번 담당자는 RecordManager.h → RecordManager.cpp → RecordTypes.h의 필드 → 기록 관련 테스트 순서로 읽어도 됩니다.

## 3. 이번 구현에서 선택한 미확정 규칙

아래는 전체 프로토타입을 실행하기 위해 선택한 기준입니다. 팀 합의가 완료되었다는 뜻은 아닙니다.

- 빈 입력·공백만 입력하면 기회를 차감하지 않습니다.
- 앞뒤 ASCII 공백은 제거하고 내부 공백은 거절합니다.
- 사람이 즉시 막히는 시작 단어는 제외합니다.
- 중단한 판은 저장하지만 승패·최고 점수에서는 제외합니다.
- 통계는 난이도를 합쳐 계산하고 각 판의 난이도는 별도 저장합니다.
- 손상 기록 초기화를 거절하면 저장을 중지하고 기존 파일을 보존합니다.
- 실행을 다시 시작하면 쉬움·힌트 OFF로 시작합니다.
- 두음법칙·시간 제한·연속 보너스는 구현 범위에 포함하지 않았습니다.
- 선택 힌트는 원안의 첫 음절·길이 방식으로 구현했습니다.

## 4. GameManager와 기록의 약속

GameManager는 끝난 판에 대해 한 번만 GameRecord를 전달합니다. 이후 포기·중단을 다시 호출해도 결과를 중복 저장하지 않습니다.

GameRecord는 결과, 최종 점수, 당시 Settings를 포함합니다. RecordManager는 점수를 재계산하지 않고 확정 값을 저장합니다. 통계는 저장에 성공한 기록 목록을 순회해 계산합니다.

로드: Ok / NotFound / InvalidFormat / ReadError  
저장: Ok / WriteError / Blocked / InvalidRecord

InvalidRecord는 호출한 쪽에서 결과 미확정, 음수 점수 등 잘못된 값을 넘겼을 때입니다.

파일 형식:

~~~text
WORDCHAIN_RECORD_V1
WIN 40 NORMAL 0 1
LOSE 20 EASY 0 0
ABORTED 100 EASY 0 0
~~~

필드는 결과 / 점수 / 난이도 / 두음 여부 / 힌트 여부입니다. 값이 잘못된 행이 있으면 전체 읽기를 실패로 처리하고 일부 기록만 정상 통계로 반영하지 않습니다.

저장은 전체 기록을 임시 파일에 쓴 뒤 교체합니다. 오류가 발생하면 이번 기록을 메모리 통계에도 추가하지 않습니다. 여러 프로그램이 동시에 같은 기록 파일을 수정하는 사용 방식은 지원 범위가 아닙니다.

## 5. Windows 한글 입력

실제 Windows 콘솔에서는 ReadConsoleW로 UTF-16 입력을 읽은 뒤 WideCharToMultiByte로 UTF-8 문자열을 만듭니다. 파일·파이프·테스트용 문자열 입력은 getline을 사용합니다. 규칙·AI·기록에 전달하는 단어는 모두 UTF-8입니다.

이 Windows 보조 코드는 ConsoleUI와 main에만 있고 나머지 역할의 핵심 로직은 C++17 표준 라이브러리로 작성했습니다.

공식 참고: [ReadConsole](https://learn.microsoft.com/en-us/windows/console/readconsole), [WideCharToMultiByte](https://learn.microsoft.com/en-us/windows/win32/api/stringapiset/nf-stringapiset-widechartomultibyte).

## 6. 수정할 때

- 공통 헤더나 함수 선언을 바꾸면 호출하는 담당과 함께 변경합니다.
- 개인 테스트 main을 전체 실행 파일에 함께 넣지 않습니다.
- data/records.txt와 .vs, bin, obj는 개인 상태·빌드 산출물입니다.
- 테스트는 별도 임시 폴더를 사용하며 기본 사전 폴더의 실제 전적에 쓰지 않습니다.
- 사전과 기록의 경로는 Application에 전달되므로 개인 PC 경로를 모듈 내부에 고정하지 않습니다.
